# 事务对话、项目记忆与首次引导

前端在 `desktop`，后端在 `server`，协议在 `shared`。本轮不替换 Direct/Harness，不改执行器权限。

## 怎么用

- 设置页顶部有首次使用引导：配置并保存模型、检查 API、创建两分钟后的体验提醒。演示检查不调用模型；在线检查发出一次短请求，消耗少量额度，不代表 Harness 或编码执行器可用。
- 在“事务 → 项目 → 某个项目”查看项目记忆，支持目标、进展、下一步和背景四类，可手动添加、编辑、删除。
- 聊天中可以要求“在数据结构项目里记住：插入完成，下一步处理删除”。管家查询项目后保存，并关联用户消息 ID。已有记忆先查后改；普通聊天不会被设计为自动提取长期记忆。
- “刚才那项完成了”使用最近工具操作的焦点；有明确标题则按标题查询，同名时返回候选，由用户确认。焦点最多保留一天，且须来自最近三条用户消息中的一次操作，不拿最新待办猜测。

## 数据与边界

项目记忆属于事务项目，和编码项目分开。记录保存于原 SQLite 的新 record kind，不迁移或覆盖旧数据；旧数据没有记忆时返回空列表。

记忆修改使用 revision，过期编辑返回 409。创建、更新、删除支持 Idempotency-Key，写入和幂等结果在同一事务中提交；重复创建请求不会重复插入，已删除记录也不会被旧创建请求恢复。删除从活动记忆列表移除；原始聊天、历史事件、幂等结果、备份不会被清除。

用户手动编辑会把当前内容来源标成手动；对话保存绑定用户消息。来源消息 ID 可追溯，前端能展示当前载入历史中的源消息，超过近期历史范围时展示 ID。记忆不代表独立验证的事实，完成状态、截止时间仍以事务/任务记录为准。

本轮增加 `resolve_agenda_reference`、`query_project_memory`、`manage_project_memory`，通过同一份 JSON schema 暴露给 Direct 与 Harness。工具提供确定的查询/存储；具体自然语言如何选工具仍取决于模型，测试不会证明所有说法都能识别。重复日程仍按系列管理，不新增“只改某一次”的能力。

## 复现与回归

1. 选择演示并保存，执行模型检查，应提示未验证在线模型。
2. 创建体验提醒，刷新/重新打开设置，应显示已创建，不重复新增。
3. 建立事务项目，添加进展记忆，编辑并刷新页面，内容应仍在；删除后活动列表为空。
4. 两个事务同名时调用 `resolve_agenda_reference`，应返回 ambiguous；不能自动修改任意一个。
5. 使用旧 revision 编辑记忆，应返回 409；用相同幂等键重放，应返回原结果且不重复写入。

后端回归：`npm run check`。前端回归：`npm --prefix desktop run check`。浏览器集成：`node node_modules/tsx/dist/cli.mjs desktop/scripts/check-personal-workflow.ts`，需要 Playwright/Chrome，可用 `PLAYWRIGHT_MODULE_PATH` 指定模块。

浏览器脚本使用隔离数据库与演示模式，检查页面流程，不等于原生系统通知验证。Direct 与真实 Harness SDK 集成使用模拟模型，未声称真实模型自然语言验收通过。
