# 继续未完成任务

从 0.2.8 起，任务列表中的“继续任务”调用 `POST /api/v1/tasks/{id}/resume`，复用原任务 ID、目录、执行器和模型。只能继续 failed、cancelled、interrupted 的任务；正在运行、排队、已完成的任务返回 409。重复点击不会新增队列条目。

Claude 的 system/result 事件一旦返回会话 ID，立即保存到任务中，不等待成功结束。继续时传入精确的 `--resume <sessionId>`，不使用可能选错任务的 `--continue`。旧任务没有记录，或用户选择“从文件继续”（请求体 `{"fromFiles":true}`），则启动新执行会话，根据原指令、现有产物、最近日志和上次错误继续工作；这种方式不是恢复模型会话。Codex、ZCode 本版也采用文件和记录续做。

之前每次的结束状态、结果和错误保存于 attempts；最近日志仍保留最多 100 条。最初的检查点不会被重新捕获或覆盖，恢复文件仍恢复到整个任务第一次执行前。原 `/retry` API 为兼容保留，语义仍为复制新任务；前端按钮和管家 `resume_task` 使用新的继续接口。

权限设置不自动变化。每次启动记录 Claude 权限模式，权限拒绝仍判为失败。实际查看到的配置已启用完全访问，当前 Claude 进程也携带 bypassPermissions；不能据此保证 Bash 一定获准，也没有足够证据断定旧错误的具体策略来源。本次没有修改 Claude 全局、项目或组织策略。解除实际阻塞后继续原任务即可。

验证覆盖失败后会话 ID/部分结果持久化、同 ID 续做、原检查点保留、重复点击、旧任务兼容及 CLI 参数。另在隔离目录使用真实已安装的 Claude 做了两轮无工具对话，第二轮用指定会话恢复并准确取回首轮测试暗号，会话 ID 一致。此验证不代表原业务任务或 Bash 权限已经通过。
