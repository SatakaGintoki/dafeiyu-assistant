# 给前端模型的交接提示词

将下面整段交给负责前端的模型即可。先确认它使用本分支或已合入本次后端提交。

---

请为“大肥鱼管家”实现通用的「事务本」前端。后端已完成，保持前后端分离：通过现有认证 REST + SSE 调用，不在前端另建任务数据库或自行模拟提醒后端，不改后端协议。科目只是项目的一种用途，文案和演示也要覆盖生活、旅行、个人项目。

先读这些文件：

1. `docs/agenda-backend.md`：功能语义、接口规则及提醒边界。
2. `shared/agenda.ts`：可直接复用的响应类型。
3. `docs/openapi.json`：`/api/v1/agenda` 接口规范。
4. `desktop/src/lib/api.ts`、`desktop/src/lib/store.ts` 及现有面板/导航/通知代码，沿用项目技术与设计习惯。

实现范围：

- 新增「事务」入口；提供今天、本周、按项目视图，以及未安排待办。原编码任务面板保持可用，事务项目与 `/api/v1/projects` 编码工作目录项目分开。
- 项目支持新建、改名、说明、归档与恢复；未分类内容显示“收件箱”。归档是暂停，不是删除。
- 待办支持标题、说明、所属项目、截止时间、提醒、完成/取消/重开。笔记只有文字。日程有起止时间、时区、提醒和每日/每周重复。
- 本周视图可以选用 FullCalendar 标准功能（评估当前版本与 React 兼容及许可证），也可以先用清楚的时间列表。大肥鱼现有面板约 440×680，优先保证小窗口可用，不硬塞宽月历。
- 日期展示按记录的 IANA timezone 转换；显示准确日期与时间。使用支持时区的转换方案，不用 `toISOString().slice(0,16)` 冒充本地输入值。
- 重复仅支持 daily/weekly、interval、weekdays、until、exceptions。编辑和完成默认影响整组，明确说明；单次例外只支持跳过日期后另建日程。
- 计划显示 draft 草案及步骤，给“确认采用 / 修改草案 / 放弃”入口。普通记事不自动生成计划。确认后调用 accept，按 itemIds 展示实际待办进度；不在浏览器逐条创建步骤，避免半成功和重复。
- 提醒用持久收件箱和卡片，操作为“知道了 / 稍后提醒 / 完成事务 / 查看”。“知道了”不等于完成。Electron 系统通知由唯一主进程负责，浏览器模式保留应用内通知。通知权限失败时给真实提示。
- 复用现有 fetch SSE 认证流，处理 agenda.changed、agenda.reminder。首次连接及 sync.required 后重新取 `/api/v1/agenda`，并刷新可见日历区间；旧 `/state` 没有事务字段。
- 处理事件前校准快照，确认通知仍 pending，防止已取消事件被回放出来。以 notification.id + deliveryGeneration 持久去重；延后到期时后端增加代次，允许同 id 再展示，即使客户端错过 snoozed 中间状态，普通内容修改不重新弹。免打扰期间不弹出新系统通知；后端停止/完全退出期间无法保证准时提醒，要诚实显示状态。
- 写操作带 Idempotency-Key，网络重试复用同键。修改带最新 revision；409 刷新并提示冲突，不自动覆盖。401 停止业务重试并显示重新连接入口，避免无限 useEffect/setState 循环。
- 使用服务端返回值确认成功，不做假成功。展示空状态、加载、错误、服务离线与保存失败。所有异步请求注意卸载和竞态，防止慢请求覆盖更新状态。

验收场景：

1. 建立“生活”“个人网站”等项目，创建待办和笔记，正确归类。
2. 创建带截止/提前提醒的待办，修改时间后旧提醒不再展示。
3. 创建每周日程，查询周视图，验证跨时区/单双周/例外日期。
4. 计划草案不产生待办；确认一次生成一次；断线重试无重复。
5. 待办完成后取消 pending/snoozed 通知；确认收到提醒不改变待办状态。
6. 重新连接/重新打开面板不会重复弹通知；snooze 到时允许再次提醒；服务离线后恢复能取回未处理通知。
7. 401、409、无 API Key 和通知权限拒绝有正确反馈。事务表单管理无需模型 API Key。
8. 新增功能不破坏原聊天、编码任务、设置、置顶、拖动、鼠标穿透等桌宠能力。

用隔离后端数据目录测试，不污染用户已安装应用的数据，不关闭正在执行的真实任务。浏览器布局验证不能替代 Electron 通知/IPC 验证，要分别报告。完成后跑相关前端类型检查/构建和必要回归测试，做 Git 提交，列出变更与测试结果。此次不自动发布 Release 或替换用户安装版本，等前后端集成验收后再打包。

若发现接口确实缺少必需能力，记录具体请求/响应需求，不偷偷改共享类型和后端让问题看似通过。

修复补充（2026-10-01）：AgendaNotification 新增可选 deliveryGeneration，旧记录缺失按 1 处理。新建提醒为 1，每次延后到期增加 1；标题修改、确认收到及普通 revision 变化不增加代次。客户端持久保存已显示的代次，兼容旧 pending 日志为第 1 代。日期比较使用时间戳，不按 ISO 字符串字典序比较。浏览器弹层应按最新 pending 集合更新/撤回，同 id 合并。
