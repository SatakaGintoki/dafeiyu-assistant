# 大肥鱼短对话设计

调研日期：2026-10-01。以下为 GitHub 项目 README 所描述的能力，未安装或审计其完整实现，也不代表其对话质量已实测。

- [AstrBot](https://github.com/AstrBotDevs/AstrBot)：即时通讯平台接入、人设设置、上下文压缩。借鉴人设与消息平台解耦的思路，保留当前桌面前后端和工具链。
- [SillyTavern](https://github.com/SillyTavern/SillyTavern)：角色提示、WorldInfo、对话配置。借鉴角色描述配合具体对话示例，不引入整套前端。
- [xiyu-ai](https://github.com/dimang01/xiyu-ai)：README 描述微信风格聊天、人设与记忆、减少机械回应。项目较新；仅参考简短、少打扰的方向，不引入关系依赖、冷战或虚构人生记忆机制。

本次独立实现，未复制第三方源码或增加依赖：

- Direct 与 Harness 共用短对话规则：闲聊通常 1-2 句，普通问答以 120 字以内为目标；不机械截断模型回答。
- 默认为普通短段落，不主动写提纲、列选项或每轮反问；需要详细解释、完整代码时按用户要求展开。
- 只把任务状态摘要放入常驻上下文；详情通过已有工具按需查询，任务通知不充当对话风格示例。
- 任务完成通知最多展示 160 字输出预览，完整结果和错误仍保存在任务详情里。预览不是模型生成的语义摘要。
- 不通过随机拖延、假装已读、虚构现实经历来营造真人感。角色表达不影响工具权限和状态真实性。

验证需区分：自动测试检查规则送达两种运行时和结果保存；真实模型的语气仍有随机性，不能保证每轮精确符合字数目标。

本次使用应用已配置的模型和凭据、隔离数据目录做了 5 条合成对话实测（4 条 Harness、1 条 Direct），未发送个人聊天历史。最后一轮回复分别为 10、40、70、36、58 字；未派发实际任务。可通过 `node node_modules/tsx/dist/cli.mjs scripts/check-conversation-live.ts` 手动复测，会消耗模型额度。观察到模型偶尔仍会习惯性反问，因此这不是“每轮像真人”的保证。
